# Livraison de test et note finale sécurisée — 6 octobre 2026

Cette livraison traite les **deux premiers points de l'audit** : réunir les changements locaux pour une version de test identifiable sur GitHub, puis sécuriser le contenu de la note finale. Elle ne reconfigure ni GPT‑OSS ni Qwen 3.6 FP4, et ne constitue pas une qualification clinique ou matérielle.

## Point 1 : une version complète à tester

La branche d'application et de test est `camera-guidance-local`. `main` reste un README d'orientation, pas une branche contenant l'application. Le README indique maintenant cette branche dans les instructions de récupération et de mise à jour, demande de préserver les modifications locales et de relever le SHA exact testé.

Les changements réunis comprennent :

- Assistant optionnel pendant la capture, découplé du traitement de pose ; personnages et guide permanents.
- Fenêtre de cinq secondes/25 observations et deux JPEG au plus, seulement après consentement visuel ; pas de vidéo enregistrée ni d'historique live exporté.
- Un slot LLM partagé entre live et note finale, sans file ; budgets totaux de 10 s/30 s pour tous les tours et outils.
- Transport HTTP local interruptible, refus des résultats tardifs, isolation des séances et protection contre les anciennes requêtes de contrôle.
- Retour caméra court contrôlé, intervalle analysé, âge et badge provisoire ; pause qui laisse la capture active.
- Retour depuis une page mise en cache sans reprise automatique de l'ancien essai.

Ces fonctionnalités existaient localement aux 2 et 5 octobre ; leurs suivis historiques restent datés. Cette page ne déduit pas une publication ou une CI distante réussie des seuls tests locaux : le commit envoyé et son résultat GitHub doivent être confirmés séparément.

## Point 2 : aucune phrase libre du modèle dans la note finale

Le modèle restitue seulement `measurement_ref`, `fact_codes` et `requires_professional_review:true`. Les codes doivent correspondre exactement à l'ensemble `supported_fact_codes` de la mesure courante : statut, caractère expérimental et réserves de qualité. Une raison inconnue est remplacée par un code générique, jamais recopiée comme texte.

L'application valide la référence et l'ensemble des faits, puis impose leur ordre et leurs phrases françaises. L'ancien champ `text`, les champs supplémentaires, doublons, omissions, faits ajoutés ou contradictoires et l'absence de revue requise sont rejetés. Aucun diagnostic, exercice, dosage, angle inventé ou nombre en lettres produit par le modèle n'est affiché. Une image peut être transmise avec les accords existants, mais n'autorise aucune conclusion supplémentaire.

En cas d'échec, `proposed_note` reste vide et le brouillon déterministe est conservé. Le harness final reste **limité au coude** ; les autres protocoles gardent leurs brouillons déterministes. La note est non validée et distincte de la mesure : le parcours professionnel d'acceptation/correction signé reste à développer.

Implémentation : [vocabulaire et validation](../packages/harness/final_note.py), [harness final](../packages/harness/runner.py), [outils de séance](../packages/harness/tools.py). Le [contrat d'intégration](tool-integration.md) décrit le schéma et les règles de compatibilité.

## Vérifications et frontière de publication

Vérification locale complète de cette livraison : **158 tests Python et 56 tests JavaScript réussis (214 au total)**, avec clients LLM, poses, médias et serveurs HTTP simulés. Les 16 nouveaux tests de la note finale couvrent les statuts, les réserves, les réponses anciennes/libres, contradictions, omissions, références, doublons JSON et codes, contenus mal formés, taille et contexte visuel. Trois régressions déterministes supplémentaires couvrent les délais socket. Python 3.11.14 ; syntaxe JavaScript et `git diff --check` sans erreur. Scan de 85 fichiers : aucun artefact interdit ni secret usuel détecté, contrôle non exhaustif.

Le [premier run distant du commit `12bee7a`](https://github.com/Matt95354855/kine-motion-local/actions/runs/37466716254) a réussi sur Linux et révélé sur Windows un timeout socket qui pouvait précéder légèrement la borne de l'horloge de contrôle. Le correctif normalise cette erreur en dépassement du budget uniquement si ce budget était la borne du socket ; l'annulation garde la priorité et un délai client plus court reste distinct. Aucun budget allongé, aucun retry, aucune assertion de délai assouplie. Le test concerné passe dix répétitions locales ; la validation du commit corrigé reste celle de son propre run GitHub.

Le SHA de la livraison est celui affiché par `git rev-parse HEAD` après récupération de la branche. Le statut de sa CI Linux/Windows est consultable dans [GitHub Actions](https://github.com/Matt95354855/kine-motion-local/actions?query=branch%3Acamera-guidance-local) ; vérifier que le commit du run correspond à celui de l'essai. Les résultats d'un ancien run ne qualifient pas cette nouvelle version.

Aucun test réel webcam, Windows/GPU, LLM FP4 ou SSH n'est acquis ici. Aucun poids, alias, URL, quantification ni paramètre de génération n'est changé. Le prompt et le contrat de sortie du harness final changent, pas la configuration d'inférence. Aucun média personnel, token ou modèle installé ne doit entrer dans le dépôt.

## Ce qui reste avant une campagne fiable

- Détecter la caméra silencieusement figée et invalider une capture incomplète ; la qualité de quelques images reçues ne prouve pas que tout le mouvement a été capturé.
- Compléter la provenance des exports : commit, hash/paramètres de pose et environnement de la campagne.
- Qualifier Windows, la détection positive d'une personne, la liaison SSH, les outils/images des deux LLM existants, les délais et la RAM/VRAM.
- Vérifier séparément que le runtime GPU abandonne une génération après déconnexion : la fermeture du transport local ne le garantit pas. Le watchdog de pose native reste également à développer.
- Contrôler les pics parasites, cadrage/stabilité, changements de personne et limites des projections 2D ; aucune validation clinique automatique.
